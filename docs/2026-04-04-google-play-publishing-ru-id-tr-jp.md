# Публикация в Google Play: Россия, Индонезия, Турция, Япония

Документ описывает **типичные требования Google Play** и **чеклист задач** для выкладки приложения в четырех целевых странах. Статусы задач (`[ ]` / `[x]`) можно обновлять по мере выполнения.

**Связь с продуктом:** мультиязычный UI и bundled-календари под регионы описаны в [плане языков и bundled](./2026-04-04-languages-and-bundled-calendars-plan.md).

---

## Цели релиза

- Доступность в **Google Play** для пользователей из **России (RU)**, **Индонезии (ID)**, **Турции (TR)** и **Японии (JP)**.
- Соответствие **политикам Google**, **формам в консоли** и **минимальным артефактам** листинга для каждой локали.

**Важно:** требования Google и нормы магазина меняются. Перед финальной подачей сверяйтесь с актуальными разделами [Play Console Help](https://support.google.com/googleplay/android-developer/) и **Policy Center** в консоли.

## Часть B — Техническая готовность Android-сборки

| ID | Задача | Примечание |
|----|--------|------------|
| **GP-B1** | [x] **Release-сборка** через **Android App Bundle (AAB)** — основной формат загрузки в Play. | Артефакт: `android/app/build/outputs/bundle/release/app-release.aab` (`.\gradlew.bat bundleRelease` из `android/`). |
| **GP-B2** | [x] Включить **подпись приложения**: **Play App Signing** (рекомендуется Google) + локальный **upload key**. | В репо: шаблон `android/keystore.properties.example`, `android/app/build.gradle` читает `android/keystore.properties` и подписывает release upload-keystore; без `keystore.properties` release временно на debug. Сгенерировать `.jks`, скопировать шаблон в `keystore.properties`, сделать backup. **Play App Signing** включается в консоли при первой загрузке AAB. |
| **GP-B3** | [x] Проверить **targetSdkVersion** и **compileSdk** на соответствие **текущим требованиям Google** к новым приложениям и обновлениям. | **Проверено 2026-04-04:** в `android/build.gradle` заданы `compileSdkVersion = 36` и `targetSdkVersion = 36` (приложение — обычный телефонный формат). По [Target API level requirements](https://support.google.com/googleplay/android-developer/answer/11926878) для новых приложений и обновлений действует минимум **API 35** (Android 15) с **2025-08-31**. **36 ≥ 35** — требование выполняется; при смене политики Google сверять страницу снова. |
| **GP-B4** | [x] Проверить **versionCode** (монотонно растёт) и **versionName** (человекочитаемо). | **Проверено 2026-04-04:** в `android/app/build.gradle` → `defaultConfig`: `versionCode 1`, `versionName "1.0"` — подходит для **первой** загрузки в Play (целое `versionCode` ≥ 1, имя версии читаемое). **Дальше:** каждый прод-релиз — строго больший `versionCode` (2, 3, …); `versionName` обновлять по своей схеме (например 1.0.1, 1.1.0). В `package.json` сейчас `"version": "0.0.1"` — для магазина решает Android; при желании выровнять с релизом вручную. |
| **GP-B5** | [x] Убедиться, что приложение **64-bit** совместимо (если применимо к вашим нативным библиотекам). | **Проверено 2026-04-04:** в `android/gradle.properties` задано `reactNativeArchitectures=armeabi-v7a,arm64-v8a,x86,x86_64` — есть **arm64-v8a** (реальные устройства) и **x86_64** (эмуляторы). В `android/app/build.gradle` нет `ndk.abiFilters`, ограничивающих только 32-bit. Нативные зависимости: Hermes (`hermesEnabled=true`), React Native и модули (`op-sqlite`, `react-native-svg` и др.) попадают в AAB с 64-bit библиотеками при такой конфигурации. Требование Google к [64-bit](https://developer.android.com/google/play/requirements/64-bit) для приложений с нативным кодом выполняется. **После релиза:** при смене `reactNativeArchitectures` не убирать `arm64-v8a`; финальную сводку ABI смотреть в **App bundle explorer** в Play Console. |
| **GP-B6** | [x] Прогнать **Internal testing** / **Closed testing** на реальных устройствах: установка из Play, первый запуск, офлайн-сценарии. | Соответствует офлайн-first архитектуре проекта. **Отмечено в чеклисте 2026-04-04.** |
| **GP-B7** | [ ] Проверить соответствие **требованиям к размеру страницы нативных библиотек** и прочим техническим предупреждениям **Pre-launch report** / **App bundle explorer** в консоли. | На момент релиза смотреть актуальные предупреждения в консоли. |
| **GP-B8** | [ ] **ProGuard/R8** (если включён): smoke-тест release-сборки без крашей на ключевых экранах. | React Native: следовать рекомендациям версии RN и списку keep rules для нативных модулей. |

## Часть C — Контент и политики в консоли

| ID | Задача | Примечание |

| **GP-C1** | [ ] Заполнить **Декларацию приложения** (App content): реклама, новостные приложения, COVID-19 и т.д. — по факту продукта. | Честные ответы; несоответствие = отклонение или удаление. |
| **GP-C2** | [ ] Пройти **опрос контентного рейтинга** (IARC / аналог в консоли). | Выдаётся возрастной ярлык по странам. |
| **GP-C3** | [ ] Заполнить **«Безопасность данных» (Data safety)**: какие данные собираются, зачем, передаются ли третьим лицам, возможность удаления и т.д. | Для офлайн-календаря с локальным JSON/SQLite часто минимальный сбор; всё равно нужно последовательно пройти все пункты формы. |
| **GP-C4** | [ ] Указать **целевую аудиторию** (в т.ч. дети / не дети) согласно реальному использованию. | Влияет на политику Families и требования к контенту. |
| **GP-C5** | [ ] При использовании **разрешений** (файлы, уведомления и т.д.) — соответствие **политике разрешений** и **понятные объяснения** в листинге/в приложении. | Документ-пикер для импорта JSON должен быть обоснован в описании. |
| **GP-C6** | [ ] Проверить раздел **«Лицензионные тестеры» / лицензии** только если есть платный контент. | Иначе можно пропустить. |
| **GP-C7** | [ ] Подготовить ответы на **«Доступ к приложению»**, если Google не сможет проверить функции без учётных данных (для этого приложения обычно не требуется). | Актуально для приложений с логином. |

## Часть E — Локализации листинга под RU, ID, TR, JP

Один и тот же бинарник может обслуживать все страны; **в консоли** добавляются **переводы листинга** (и при необходимости **скриншоты с текстом на языке пользователя**).

| ID | Задача | Примечание |
|----|--------|------------|
| **GP-E1** | [ ] **Русский (RU)** — заголовок, короткое/полное описание; скриншоты с RU UI. | Основной рынок; проверить соответствие формулировок данным календаря РФ. |
| **GP-E2** | [ ] **Индонезийский (id)** — тексты листинга; скриншоты с UI на `id`. | В приложении уже есть `id` и bundled IDN — листинг должен совпадать по обещаниям. |
| **GP-E3** | [ ] **Турецкий (tr)** — тексты листинга; скриншоты с UI на `tr`. | Аналогично для `calendar2026TR.json` / локали TR. |
| **GP-E4** | [ ] **Японский (ja)** — тексты листинга; скриншоты с UI на `ja`. | Для JP часто важны аккуратная типографика и точные формулировки в описании. |
| **GP-E5** | [ ] **Английский (en)** — базовый листинг для международной витрины и пользователей с EN-локалью. | Рекомендуется как default или параллельно с RU. |
| **GP-E6** | [ ] Вычитка носителями (хотя бы spot-check) для **id / tr / ja** описаний. | Снижает риск неловких автопереводов. |

## Часть H — Заметки по целевым странам (не техническая настройка Play)

Это **не замена** юридической консультации; для коммерческих и налоговых вопросов привлекайте специалистов.

| Страна | На что обратить внимание |
|--------|---------------------------|
| **Россия** | Пользователи привыкли к **русскому** листингу и поддержке. Часть аудитории также использует **альтернативные магазины** (например RuStore) — выход только в Google Play не покрывает 100% рынка; отдельное решение по дистрибуции при необходимости. |
| **Индонезия** | Сильный мобильный рынок; **локализованное описание** и скриншоты на **Bahasa Indonesia** повышают доверие. |
| **Турция** | **Турецкий** листинг и UI (`tr`) согласованы с календарём TR; цены/налоги — через настройки Merchant при монетизации. |
| **Япония** | Высокие ожидания к **качеству UI/копирайта**; японский листинг (`ja`) и корректные **даты/локаль** в скриншотах важны для доверия. |

## Сводный порядок работ (как идти по задачам)

1. **GP-A*** — аккаунт, юридика, политика конфиденциальности.  
2. **GP-B*** — стабильная подписанная AAB, соответствие SDK, внутренние тесты.  
3. **GP-C*** — декларации, рейтинг, безопасность данных.  
4. **GP-D*** + **GP-E*** — листинг и четыре локали + EN.  
5. **GP-F*** — страны и цены.  
6. **GP-G*** — internal → closed → production.  
7. **GP-I*** — уточнения про данные и поддержку.

---

## Критерий «готово к подаче в Production»

- [ ] Все обязательные разделы консоли без предупреждений блокирующего типа.  
- [ ] AAB успешно обработан, подписан, тестовая установка из трека работает.  
- [ ] Листинг на **ru, id, tr, ja** (и базовый **en**) согласован с реальными возможностями приложения.  
- [ ] Страны **RU, ID, TR, JP** включены в дистрибуцию (если это цель релиза).  
- [ ] Политика конфиденциальности и форма «Безопасность данных» согласованы между собой.
