## Реализованные изменения

### 1. Контракт входных данных

Описан raw-формат импортируемого календаря:

- `year`
- `holidays[]`
- `weekends[]`
- `preholidays[]`

Для праздников зафиксирован объект со следующими полями:

- `date`
- `name_ru`
- `name_en`

### 2. Доменная модель

Описаны основные доменные типы:

- `CalendarYear`
- `CalendarDay`
- `DayType = workday | weekend | holiday | shortened`

Для каждого дня после нормализации формируется полная запись:

- `date`
- `year`
- `month`
- `day`
- `weekday`
- `type`
- `holidayNameRu`
- `holidayNameEn`
- `isShortened`
- `workHours`

### 3. Цепочка обработки данных

Реализована единая и детерминированная цепочка:

- `parseCalendarImportJson`
- `validateCalendarImportData`
- `normalizeCalendarImport`
- `parseValidateAndNormalizeCalendarImport`

Это дает одну общую дорожку для:

- bundled `calendar2026.json`
- будущего пользовательского импорта `JSON`

### 4. Валидация

Добавлена строгая валидация входных данных:

- проверка, что корень JSON является объектом
- проверка обязательных полей
- проверка типа каждого поля
- проверка формата дат `YYYY-MM-DD`
- проверка, что дата реально существует
- проверка, что дата принадлежит заявленному году
- проверка дублей в `holidays`, `weekends`, `preholidays`
- проверка непустых `name_ru` и `name_en`

Ошибки валидации сделаны структурированными и пригодными для UI:

- `CalendarImportValidationError`
- `issues[]` с `code`, `message`, `path`

### 5. Нормализация

Импорт нормализуется в полный список дней года без пропусков и дублей.

Зафиксирован явный приоритет типов дня:

- `holiday`
- `shortened`
- `weekend`
- `workday`

Также добавлен расчет рабочих часов:

- `workday` -> `8`
- `shortened` -> `7`
- `holiday` и `weekend` -> `0`

## Результат этапа

После выполнения этого этапа проект уже умеет безопасно превращать `calendar2026.json` в полный доменный календарный год.
