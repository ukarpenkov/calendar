# Release notes — версия 9.0

## Release notes (для магазина и пользователей)

**Версия 9.0**

- **Открытие приложения с виджета** — нажатие на виджет календаря на домашнем экране открывает приложение, как при запуске с иконки.
- **Автообновление виджета в новый день** — виджет чаще обновляется сам при наступлении нового календарного дня, без обязательного открытия приложения: планирование полуночного обновления запускается при добавлении виджета, используется более надёжный будильник на полночь, учтены перезагрузка устройства, смена часового пояса и ручная установка времени.

## Что изменено

### Версия релиза

- В Android (`android/app/build.gradle`): `versionName "9.0"`, `versionCode 9`.
- В настройках экран «О приложении» показывает **9.0** через `APP_DISPLAY_VERSION` в `src/shared/config/appDisplayVersion.ts`.

### Открытие приложения по нажатию на виджет

- На корневой контейнер виджета (`OverlapWidget`) в `CalendarWidgetLayout` для обоих состояний (нет данных / есть данные за сегодня) добавлено **`clickAction="OPEN_APP"`** (`react-native-android-widget`).
- Открытие обрабатывается нативно в провайдере виджета (`getLaunchIntentForPackage` → `startActivity`), без лишнего JS-обработчика для этого сценария.
- Поведение едино для фонового и ручного обновления виджета из приложения.

### Улучшенное автообновление при смене дня

- **Планирование с момента добавления виджета:** `CalendarAppWidgetProvider` при `onEnabled` и `onUpdate` вызывает `scheduleNextMidnight`, чтобы цепочка полуночных обновлений стартовала без запуска UI приложения.
- **Более точный будильник:** в `CalendarWidgetAlarmScheduler` вместо `setWindow` используется **`setAlarmClock`** — срабатывание ближе к локальной полночи, меньше задержек в Doze.
- **Expedited WorkManager** (API 31+): headless-отрисовка виджета после broadcast не зависает в очереди до открытия приложения (патч `react-native-android-widget`).
- **Дополнительные триггеры:** `CalendarWidgetBootstrapReceiver` реагирует на `BOOT_COMPLETED`, `TIMEZONE_CHANGED` и **`ACTION_TIME_CHANGED`** (`TIME_SET` в манифесте); подстраховка при старте процесса в `MainApplication` и при возврате приложения в `active` в `App.tsx`.
- JS-регистрация виджета и task handler используют имя провайдера **`CalendarAppWidgetProvider`**.

## Что проверено

- Сборка `:app:compileDebugKotlin` проходит успешно.
- Константа `APP_DISPLAY_VERSION` совпадает с `versionName` в Gradle.
- По исходникам `react-native-android-widget`: `OPEN_APP` открывает приложение без запуска JS-задачи `WIDGET_CLICK`.

## Дальнейшие шаги

- На устройстве: после установки 9.0 проверить тап по виджету (при необходимости снять виджет с экрана и добавить снова).
- Проверить смену даты без открытия приложения (ожидание полуночи или смена даты в настройках системы) — виджет должен показать новый день.
- На прошивках с агрессивным энергосбережением при редких сбоях можно добавить подсказку об исключении приложения из оптимизации батареи.
- При публикации собрать `bundleRelease` (AAB) и загрузить в Google Play Console с `versionCode 9`.
