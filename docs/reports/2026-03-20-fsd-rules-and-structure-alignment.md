# Отчет: FSD-правила и выравнивание структуры

Дата: `2026-03-20`

Источник задачи: пользовательский запрос на добавление правил про `Feature-Sliced Design` и обязательные отчеты в `docs/reports`

## Что было сделано

Добавлены постоянные правила для проекта:

- использование `Feature-Sliced Design` в `src/`
- обязательное хранение отчетов по задачам в `docs/reports`

Также обновлено базовое архитектурное правило, чтобы оно не конфликтовало с FSD-подходом.

## Изменения в структуре

Текущая плоская структура `src` была приведена к FSD-слоям:

- `src/app/App.tsx` — приложение и bootstrap-уровень
- `src/entities/calendar/model/types.ts` — доменные типы календаря
- `src/features/calendar-import/model/*` — типы и логика импорта календаря

Добавлены публичные API файлов:

- `src/entities/calendar/index.ts`
- `src/features/calendar-import/index.ts`

Старые плоские файлы из корня `src` удалены после переноса.

## Что было обновлено

- `index.js` теперь импортирует приложение из `src/app/App`
- тесты обновлены на новые FSD-пути
- `docs/reports/README.md` дополнен ссылкой на этот отчет

## Что проверено

Фактически выполненная проверка:

- `npm test -- --runInBand`
- `npx tsc --noEmit`
- диагностика по измененным файлам через встроенный линтер

## Результат

Проект получил явное правило по FSD и уже приведен к нему на текущем объеме исходников.

Отдельно зафиксировано правило, что отчеты по выполненным задачам пишутся в `docs/reports`.
