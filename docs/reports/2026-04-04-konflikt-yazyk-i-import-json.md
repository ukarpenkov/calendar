# Конфликт смены языка и пользовательского импорта JSON

## Что изменено

- В SQLite (`app_metadata`) добавлен ключ `active_calendar_user_json_import`: значение `1` означает, что активный год последним был записан из потока импорта локального JSON.
- `replaceActiveYear` принимает второй аргумент источника: `'user_json_import'` (ставит флаг) или `'bundled'` (удаляет флаг). По умолчанию — `'bundled'` (сидирование и синхронизация с bundled).
- Смена региона bundled передаёт **причину** в обработчик: `settings` (настройки) или `app_language` (привязка к языку в `App.tsx`). Для `app_language` при установленном флаге импорта `syncActiveYearWithBundledRegion` **не** вызывает `replaceActiveYear`, чтобы не затирать пользовательский календарь. Явный выбор региона в настройках по-прежнему выполняет замену на bundled и сбрасывает флаг.
- В настройках под переключателем языка показывается подсказка `settings.rows.language.userImportHint`, если активный год пришёл из импорта (тексты для `en`, `ru`, `tr`, `id`, `ja`).
- План `docs/2026-04-04-languages-and-bundled-calendars-plan.md` (п. 6 и строка 3.3) обновлён под принятое поведение.

## Что проверено

- `npm test`: юнит-тесты репозитория (флаг metadata, сброс после bundled replace), `syncActiveYearWithBundledRegion` (пропуск при `app_language` + импорт; замена при `settings`).

## Дальнейшие шаги

- Установки без флага (импорт до обновления) по-прежнему ведут себя как «нет пользовательского импорта» до следующего импорта или замены из bundled.
- При желании можно добавить диалог подтверждения при смене языка вместо тихого пропуска — сейчас выбрано ненавязчивое сохранение данных и текст в настройках.
