# Спецификация: Отпуск (Vacation)

## 1. Обзор

Новый функционал «Отпуск» позволяет пользователю добавлять периоды отпуска в календарь. Отпуск — это пользовательский тип дня, который отображается на календаре выделенным цветом с подписью-комментарием и имеет свою картинку в приложении и виджете.

---

## 2. UI/UX

### 2.1 Кнопка «Пальма» (экран года)

- На экране года (`YearHomeScreen`) рядом с кнопкой настроек (шестерёнка) добавляется новая кнопка — **иконка пальмы**.
- Кнопка отображается **только на экране года**, на экране месяца — нет.
- Иконка должна быть цветной, выразительной, в стиле приложения.
- При нажатии открывается **модальная форма управления отпусками**.

### 2.2 Форма управления отпусками

Модальное окно (bottom sheet или полноэкранный экран), содержащее:

#### 2.2.1 Форма добавления/редактирования отпуска

| Поле | Описание |
|------|----------|
| **Дата начала** | Date picker (красивый, в стиле приложения) |
| **Дата конца** | Date picker (красивый, в стиле приложения) |
| **Комментарий** | Короткий текстовый ввод (например, «Отдых на море») |
| **Цвет** | Выбор из предложенной палитры цветов (визуальные чипы/свотчи) |

- Валидация: дата конца ≥ дата начала, даты не должны пересекаться с уже существующими отпусками (или можно разрешить — TBD).
- Кнопка «Сохранить» / «Отмена».

#### 2.2.2 Список существующих отпусков

- Отображается ниже формы или на отдельной вкладке.
- Каждый элемент списка показывает: период, комментарий, цветовой индикатор.
- Действия: **Редактировать** (открывает форму с заполненными данными), **Удалить** (с подтверждением).

### 2.3 Отображение отпуска на календаре

#### 2.3.1 Экран года (YearHomeScreen)

- Дни отпуска окрашиваются в **выбранный пользователем цвет** (вместо стандартного цвета типа дня).
- При этом базовый тип дня (workday/weekend/holiday) сохраняется — отпуск это **оверлей**, а не замена типа.

#### 2.3.2 Экран месяца (MonthDetailScreen)

- Дни отпуска окрашиваются в выбранный цвет.
- Под ячейкой дня (или в карточке выбранного дня) отображается **подпись-комментарий** из отпуска (аналогично тому, как праздники показывают `holidayName`).
- В `HolidayBanner` для дней отпуска отображается **своя картинка отпуска**.

### 2.4 Виджет

- Если текущий день попадает в отпуск, виджет отображает **картинку отпуска** (вместо стандартной картинки дня).
- Подпись на виджете показывает комментарий отпуска (аналогично названию праздника).

## 3. Данные

### 3.1 Типы (TypeScript)

```typescript
// Новый тип — расширение существующей системы
interface Vacation {
  id: string;               // UUID
  startDate: string;        // "2026-07-01"
  endDate: string;          // "2026-07-14"
  comment: string;          // "Отдых на море"
  color: string;            // hex цвет, напр. "#4FC3F7"
  createdAt: string;        // ISO timestamp
}
```

> **Примечание:** `DayType` остаётся без изменений (`'workday' | 'weekend' | 'holiday' | 'shortened'`). Отпуск — это **дополнительная мета-информация** к дню, а не новый тип дня. День может быть одновременно `workday` и иметь отпуск.

### 3.2 Хранение (SQLite)

Новая таблица `vacations`:

```sql
CREATE TABLE vacations (
  id          TEXT PRIMARY KEY,
  start_date  TEXT NOT NULL,  -- "2026-07-01"
  end_date    TEXT NOT NULL,  -- "2026-07-14"
  comment     TEXT NOT NULL DEFAULT '',
  color       TEXT NOT NULL,  -- "#4FC3F7"
  created_at  TEXT NOT NULL   -- ISO timestamp
);
```

Индекс для быстрого поиска отпусков по дате:
```sql
CREATE INDEX idx_vacations_dates ON vacations(start_date, end_date);
```

### 3.3 Репозиторий

Новый `VacationRepository` (или расширение существующего `CalendarRepository`) с методами:
- `getAll(): Vacation[]`
- `getByDate(date: string): Vacation | null` — найти отпуск, покрывающий эту дату
- `getByDateRange(startDate, endDate): Vacation[]`
- `create(vacation: Omit<Vacation, 'id' | 'createdAt'>): Vacation`
- `update(vacation: Vacation): void`
- `delete(id: string): void`

## 4. Архитектура (FSD)

### 4.1 Новые/изменённые слои

| Слой | Изменения |
|------|-----------|
| `entities/calendar` | Новый тип `Vacation`, расширение `CalendarDay` (поле `vacation?: Vacation`) |
| `entities/calendar/model` | Новый `vacation-repository.ts` |
| `features/vacation-management` | Новая фича: UI формы, логика CRUD |
| `pages/year` | Кнопка пальмы, передача `onOpenVacations` |
| `shared/lib/db` | Миграция: создание таблицы `vacations` |
| `shared/ui` | Компонент `VacationForm`, `VacationList`, `DatePicker`, `ColorPicker` |
| `widgets` | Расширение `widgetData.ts` и `imageMapping.ts` для отпуска |
| `entities/calendar/lib/presentation` | Новые цветовые токены для отпускного оверлея |

### 4.2 Поток данных

```
VacationRepository (SQLite)
  → CalendarDay.vacation (при загрузке года)
    → YearViewCache (цвет + подпись)
      → YearHomeScreen (окрашивание ячеек)
      → MonthDetailScreen (окрашивание + баннер + карточка дня)
    → WidgetData (картинка + подпись)
      → CalendarWidgetLayout
```

### 4.3 Навигация

Расширение `ReadyScreen` union в `user-flow.ts`:
```typescript
| { name: 'vacations' }
```

В `AppContent` добавляется условие для рендера `VacationScreen`.

## 5. Картинки

- Для отпуска нужна **одна или несколько картинок** (webp для приложения, drawable для виджета).
- Картинка отображается в `HolidayBanner` когда выбранный день — отпускной.
- В виджете — фоновая картинка отпуска.
- Вопрос: одна универсальная картинка «отпуск» или набор (море, горы, город и т.д.)? — **TBD**.

## 6. Миграция

- При обновлении приложения: автоматическая миграция SQLite (создание таблицы `vacations`).
- Существующие данные не затрагиваются.

## Вопросы от UX/UI дизайнера

1. **Расположение кнопки пальмы**: справа от шестерёнки ✅

2. **Форма отпусков**: полноэкранный экран ✅
   - Основной экран — форма создания нового отпуска:
     - Выбор начала и конца даты
     - Палитра цветов (8 цветов)
     - Поле комментария
     - Кнопки OK и Отмена внизу
   - OK → переход на экран года; отпуск появляется в VacationScreen
   - **VacationScreen** (список существующих отпусков) — доступен через бургер-меню
   - Бургер-меню появляется **только на экране VacationScreen**

3. **DatePicker**: кастомный ✅ (единый стиль с приложением)

4. **Палитра цветов**: 8 цветов ✅

5. **Пересечение отпусков**: если два отпуска пересекаются по датам — как отображать? Один цвет поверх другого? Приоритет последнего?

6. **Оверлей отпуска на ячейке дня**: как именно визуально? Это фоновый цвет ячейки (как сейчас workday/weekend)? Или рамка? Или точка/индикатор?

7. **Подпись на ячейке дня в годовом обзоре**: показывать ли подпись отпуска в миниатюрных ячейках года? Там мало места — может быть только цвет?

8. **Картинка отпуска**: одна универсальная картинка (пальма/пляж) или набор из 3-5 картинок, которые рандомно/по выбору подставляются?
